Missing values are a common feature of proteomics data. How many there are can vary substantially depending on the experimental design and the acquisition method used. Before filtering, it’s important to understand how many values are missing and how they are distributed across samples and proteins.

4.1 Missing values (Part I): fractions

When processing correlation profiling data, handling missing values is a crucial first step to ensure reliable downstream analysis. Missing values can arise for a variety of reasons, including low peptide abundance, stochastic detection, or technical issues. Alternatively, missing values can be biologically meaningful with proteins only distributed over a subset of biochemical fractions. To address this, we first filter column-wise, removing samples (fractions) with an excessive proportion of missing data, which helps avoid bias from poorly quantified replicates. Next, we filter row-wise, removing precursor peptides that are missing in too many samples, ensuring that the remaining dataset contains sufficient information for accurate subcellular localisation and machine learning classification. This two-step approach balances data completeness with retention of informative features.

4.1.1 Overall presence of missing values

It is important to assess the frequency and distribution of missing values in any dataset before deciding how to handle them. Recall that the quantitative data and, therefore, missing values are stored in the assay slot of our SummarizedExperiment.

The way that proteomic software encode missing values varies, so it is good practice to check for 0, NA and NaN values within the data. Therefore, we start by examining the DIA-NN output to determine how missing values are represented.

## Does the data contain any zeros?
qf[["precursors_filtered"]] |>
  assay() |>
  longForm() |>
  filter(value == 0) |>
  nrow()
[1] 0

The data does not contain any zeros.

If the data did contain zeros we would need to convert them to NA, because this is how QFeatures expects missing data to be denoted. To do so, we would use the zeroIsNA function.

qf <- zeroIsNA(qf, i = "precursors_filtered")

In this case, since we had no zero values, the code above should have made no changes to our data. Let’s see if we have missing values encoded as either NAs or NaNs.

## Does the data contain NAs?
qf[["precursors_filtered"]] |>
  assay() |>
  longForm() |>
  filter(is.na(value) == TRUE) |>
  nrow()
[1] 2838131

Yes, it does. Let’s explore missingness on (1) column-wise and then later, (2) row-wise levels.

4.1.2 Column-wise filtering of fractions/samples

The first step in handling missing values is to filter samples based on their overall completeness. Column-wise filtering identifies and removes samples/fractions that have an excessive proportion of missing values, which could bias downstream analyses. By excluding poorly quantified samples, we ensure that the dataset retains only those samples with sufficient coverage across peptides. This step improves the reliability of subsequent row-wise filtering, clustering, and machine learning classification, while preserving the overall structure and integrity of the dataset.

NoteConsiderations for fraction removal

This DIA-LOP experiment represents a “static” setup, where the goal is to generate a cell-wide protein map for a single condition. In contrast, in a comparative experiment, we compare subcellular fraction profiles across two or more conditions. In that case, removing fractions requires caution, because the shape of the profiles is what informs localisation and protein movement between organelles. Current methods for detecting changes in localization depend on having the same number of fractions across replicates and conditions. Removing a problematic fraction would therefore require removing the corresponding fraction in all samples. In our case, this is not a concern, because we are building a map for a single condition. All fractions and replicates will be concatenated and carry equal weight before machine learning classification.

4.2 Intensity-based filtering

Non-specific filtering by summing precursor intensities across rows (per replicate) allows us to identify features that contribute very little to the overall signal. Precursors whose total intensity represents less than 10% of the overall dataset provide limited quantitative information and are more likely to be dominated by noise. Removing these low-contributing precursors reduces technical variability, improves the signal-to-noise ratio, and focuses downstream analyses on features that meaningfully reflect protein abundance and subcellular localisation patterns. This approach helps ensure that clustering, profile visualisation, and machine learning classification are driven by reliable and informative signals.

In the below code we sum the intensity across each precursor profile and then examine the distribution.

## Calculate rowSums across profiles
rs <- qf[["precursors_subset"]]  |> 
    assay() |> 
    rowSums(na.rm = TRUE)  

## Add rowSums to rowData
rowData(qf[["precursors_subset"]])$precursor_sum_intensity <- rs

## Get quantiles
rsq <- quantile(rs, probs = c(0.05, 0.1, 0.2, 0.3))

## Plot
rs |>  
  as_tibble() |>  
  ggplot(aes(x = log10(value))) +
  geom_histogram(binwidth = 0.05) +
  geom_vline(xintercept = log10(rsq), linetype = "dashed", color = "red") +
  labs(x = "log10(Sum Intensity)", y = "Frequency") +
  ggtitle("Sum Intensity QC") +
  theme_bw()

The summed intensity per precursor across all fractions is approximately normally distributed. The red lines indicate the log10-transformed summed intensity corresponding to the quantile thresholds tested. We see a threshold of 10–30% of the total signal distribution provides a practical balance between sensitivity and robustness. Precursors contributing below this level typically fall at the lower end of the dynamic range, where measurements are more variable and noise-prone. Removing these features improves signal-to-noise ratio and stabilises downstream analyses. Lower thresholds (e.g. 10%) are more permissive, while higher thresholds (e.g. 30%) favour robustness. Users are encouraged to explore different cut-offs and assess their impact, as the optimal threshold will depend on the specific dataset and analytical objectives.

4.3 Subsetting data into replicates

If you have replicated data it is necessary to subset the data by replicate (i.e., per complete biochemical gradient) prior to calculating row-wise (precursor peptide) missingness. When all replicates are combined, missing values can be obscured or diluted, making it difficult to detect replicate-specific issues. By examining each replicate separately, we can identify systematic problems affecting individual runs—such as fraction-specific MS performance issues—rather than confounding these with biological variation. This replicate-level assessment ensures that decisions about filtering or removal are based on technical data quality within each run, rather than aggregated summaries across the entire dataset.

Information on the replicate structure has already been added to the QFeatures object during data import and is found in the colData slot under Replicate.

4.4 Missing values (Part II): precursors

Once column-wise missingness has been assessed, we apply row-wise filtering to remove peptides absent in a high proportion of fractions. Frequently missing peptides provide limited information for subcellular localisation and may introduce noise into clustering and machine learning analyses. However, filtering must be applied carefully, as overly stringent thresholds can remove genuine biological signal, particularly for proteins that are strongly enriched in a single compartment and therefore naturally sparse across the fractionation profile.

This is especially relevant for label-free experimental designs. Although DIA generally provides more consistent measurements across runs, low-abundance or highly compartment-specific proteins may fluctuate around the detection threshold. As a result, biologically meaningful, singly localised proteins can appear partially missing rather than truly absent. Strict row-wise filtering may therefore bias the dataset towards highly abundant or broadly distributed proteins.

The appropriate missing value threshold depends on the specific dataset. Users are encouraged to explore different levels of allowable missingness and assess their impact on downstream analyses. Ultimately, the number of missing values permitted per replicate should be considered relative to the total number of fractions in the experiment. Let’s do some exploration.

NoteAn additional note on label-based vs. label-free missing values

Our previous workflow ((Hutchings and Breckels 2025)) focused on a use-case with DDA TMT-based peptide quantitation. When using a DDA TMT approach, TMT co-isolation interference often results in very low abundance values where there should really be a missing value. As a result, despite the potential for MNAR values due to biochemical fractionation, TMT correlation profiling based experiments tend to have a low proportion of missing data. This means that the datasets require minimal filtering and imputation. By contrast, label-free datasets have a much high proportion of missingness. This is the case for several reasons. Firstly, label-free samples are each run independently on the MS rather than being multiplexed as is done for label-based methods. For DDA label-free experiments this means that different peptides are measured across different samples, thus leading to lots of missing values. This effect is seen in all DDA label-free proteomics experiments but is even more dramatic for correlation profiling data as most approaches rely on selecting the top N most abundant precursor peptides for analysis, but the most abundance peptides are expected to be different across fractions of the biochemical gradient. In DIA label-free correlation profiling experiments, as we show in this course, missingness is not due to the stochastic selection of precursors ions but rather due to the fact that missing values present as truly missing, with no co-isolation interference to buffer the effect of biochemical fractionation. As a result of greater missingness, users should spend more time testing combinations of filtering and imputation for label-free correlation profiling experiment data.

4.5 Imputation

As we have seen, the data still contain missing (NA) values. This is expected, because our row-wise filtering only removed precursors quantified in fewer than two of the nine fractions per replicate (i.e. more than seven missing values). How many missing values remain, and how they are distributed across the gradient, depends on the experimental design and the acquisition method. For example, label-free (LFQ) methods typically produce more missing values than label-based approaches such as TMT. Among label-free methods, DDA datasets usually contain more missing values than DIA datasets.

Imputation was discussed in our previous workflow (Hutchings et al. 2023). Rather than recommending a single approach, we encourage users to decide for themselves whether, and how, to deal with missing values in their own data. A key question is whether values are missing for biological or technical reasons.

In several label-based datasets we found very few missing values, and those that did occur tended to be at the ends of the gradient. This suggests they are missing for biological reasons: the protein is genuinely low or absent in those fractions. Removing these precursors would therefore risk losing biologically meaningful information. Similarly, in label-free DIA-LOP data we found that much of the missingness was shared between matching fractions across replicates, again pointing to biological rather than technical causes.

Missing values can be imputed with the impute() function in QFeatures. Several imputation methods are available, and they can be combined into a mixed strategy, for example using one method for values thought to be missing for biological reasons and another for values missing at random.

4.5.2 Mixed imputation

In this next section of the course we show how to implement a mixed imputation approach using the impute() function in QFeatures. Mixed imputation is useful when the data contain a mixture of values missing at random (MAR) and missing not at random (MNAR). Deciding which missing values belong to each category is extremely challenging. As an example, it seems reasonable to assume that proteins with narrow abundance distributions across the gradient will have more missing values per precursor, because they are genuinely absent from many fractions. This is the case for mitochondrial proteins in this dataset. These are biologically meaningful MNAR values. By contrast, values missing for technical reasons (MAR) should be spread evenly across the dataset and occur at low frequency for any given precursor. We therefore treat precursors with two or fewer missing values as MAR, and those with more than two as MNAR. This strategy is for demonstration only, and users should test different approaches on their own data.

We first create a logical vector with one value per precursor, indicating whether its missing values should be treated as MAR (TRUE) or MNAR (FALSE). We add this, along with the number of missing values per precursor, to the rowData of each replicate.

for (i in rep_id) {
  ## Define MAR if <= 2 missing values, otherwise MNAR
  tf <- rowData(qf[[i]])$nNA <= 2
  
  ## Append this information to the dataset
  rowData(qf[[i]])$randna <- tf
}

NoteDo I have to impute?

Not always. Robust summarisation during aggregation (e.g. MsCoreUtils::robustSummary in aggregateFeatures()) can estimate protein-level values from incomplete precursor data. In practice, however, it does not always cope with highly sparse data or proteins with many precursors. Many classifiers used for spatial proteomics, such as those in pRoloc, also require a complete data matrix. The alternative, removing incomplete profiles, risks losing the sparse, sharply enriched profiles of singly localised proteins.

TipKey Points
  • Missing values are common in proteomics data. Always check how they are encoded (zeros or NA) and assess how many there are, and where, before filtering or imputing.
  • Column-wise filtering removes fractions with excessive missingness (here > 75%). If high missingness occurs in different fractions across replicates, a technical rather than biological cause is likely.
  • In comparative/dynamic experiments, removing a fraction means removing the same fraction from every replicate and condition, so that profiles stay comparable.
  • Intensity-based filtering removes precursors at the low end of the dynamic range, where measurements are noisier. The threshold is a trade-off between sensitivity and robustness and should be explored for each dataset.
  • Row-wise missingness should be assessed per replicate (complete gradient), so that replicate-specific problems are not hidden by combining the data.
  • Row-wise thresholds must be set relative to the number of fractions. Overly strict filtering removes sharply enriched, singly localised proteins and biases the data towards abundant, broadly distributed proteins.
  • In subcellular proteomics, many missing values are biological (MNAR): the protein is genuinely low or absent in some fractions. These should not be treated in the same way as technical, random (MAR) missingness.
  • Mixed imputation with impute(method = "mixed") applies different methods to MAR and MNAR values. How values are assigned to each category is a modelling choice and should be tested on your own data.
