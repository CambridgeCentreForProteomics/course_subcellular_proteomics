8.1 Introduction

In the previous lesson we curated a set of markers that are reliable and representative of the structure of our U-2 OS data, and stored them in the markers column of our msn object. We can now use these markers to predict the localisation of the remaining proteins (currently annotated as “unknown”) using supervised machine learning. Whilst unsupervised methods such as hierarchical clustering and HDBSCAN are able to discover tight clusters of proteins with similar behaviours, these algorithms tend to struggle when it comes to identifying compartment borders. There are a number of supervised and semi-supervised machine learning algorithms available within the pRoloc infrastructure and these differ with respect to their data output, interpretability, and computational demand. Ultimately, the choice of algorithm is up to the user and we would recommend trying multiple models to determine which works best on a given set of data and biological question of interest.

The pRoloc package provides a wide range of machine learning methods for predicting protein localisation, described in its dedicated vignette “Machine learning techniques available in pRoloc”. We have also published three workflows showing how to apply these methods to correlation profiling data: one using classical machine learning (Breckels et al. 2018), one using Bayesian machine learning (Crook et al. 2019), and one covering both (Hutchings et al. 2025). In this course we focus on two complementary approaches. We start with a Support Vector Machine (SVM), a widely used classical classifier, and then move on to a Bayesian approach based on t-augmented Gaussian mixture (TAGM) models. Rather than giving only a single best guess, TAGM also estimates how confident we can be in each prediction and allows for proteins that do not fit any of the known compartments. We focus on how to apply these methods and interpret their results rather than on the details of the algorithms. Participants who want to learn more about TAGM are referred to Crook et al. (2018) and Crook et al. (2019).

Remember that a supervised classifier can only assign proteins to the compartments represented in the training data. Any compartment we removed from the marker list in the previous lesson, such as the actin cytoskeleton, cannot be predicted.

8.2 Classification using a Support Vector Machine

Support Vector Machines (SVMs) have been widely used for protein subcellular localisation prediction (Itzhak et al. 2016; Orre et al. 2019; Christoforou et al. 2016; Geladaki et al. 2019; Mulvey et al. 2017; Schessner et al. 2023). To understand how an SVM works, imagine each protein as a point in space, with one axis per fraction (here, 27 axes). Marker proteins from different compartments sit in different regions of this space. An SVM learns boundaries (hyperplanes) that separate these regions, placing each boundary as far as possible from the markers on either side. Unknown proteins are then classified according to which side of the boundaries they fall on. For more details about SVM algorithms readers are directed to Noble (2006).

Real compartments rarely have straight-line boundaries, so the SVM uses a kernel that allows the boundaries to curve. Two parameters control this, and we will optimise both below:

  • sigma controls how flexible (curved) the boundaries can be.
  • cost controls how strictly the boundaries must separate the markers. A high cost penalises misclassified markers heavily, while a low cost tolerates some in exchange for simpler boundaries.

For each protein, the SVM also returns a score reflecting how far it lies from a boundary: proteins deep within a compartment’s region get high scores, whereas proteins near a boundary get low scores. The score is a measure of confidence, but it is not a probability.

NoteThe four steps of SVM classification in pRoloc
  1. Optimise the SVM parameters sigma and cost using the markers (svmOptimisation)
  2. Check the results of the optimisation (getF1Scores, levelPlot) and extract the best parameters (getParams)
  3. Classify all proteins using these parameters (svmClassification)
  4. Threshold the predictions so that only confident assignments are kept (orgQuants, getPredictions)

8.2.1 Optimising SVM parameters

As is the case with most supervised learning models, before we can perform any classification the model parameters need to be optimised. We adopt a classical view of training the model parameters and split the data into training and testing sets. By default in pRoloc all methods allocate 80% of the labelled data (marker proteins) for training and optimisation via cross-validation of the free parameters, namely sigma and cost. The remaining 20% labelled data acts as the test set to which the optimised parameters are applied in order to calculate F1 scores. Briefly, an F1 score can be used as a measure of model accuracy as it combines measurements of both precision and recall. A higher F1 score indicates a better quality classifier.

In pRoloc the SVM optimisation process is facilitated by the svmOptimisation function. We pass our MSnSet object (here, msn) to the svmOptimisation function and tell it the name of the fData column where our markers are held (here "markers"). We use the times argument to specify how many iterations of cross-validation to complete and the xval argument to set the value of n in n-fold cross validation. Here, we will use the default 5-fold cross-validation (xval = 5) with 10 iterations (times = 10). We would typically set times = 100, but we use 10 here to keep the run time manageable; 100 iterations can take an hour or more on a laptop. Since our training data contains asymmetric class sizes (subcellular compartments with variable numbers of marker proteins), we also set class weights using the class.weights argument to avoid biasing our localisation towards compartments with a greater number of marker proteins (Huang and Du 2005). Hence, we weight each subcellular compartment by the inverse of the number of marker proteins it has. Finally, to ensure reproducibility of our results we set a seed using the seed argument.

## Get the number of markers per class
marker_tbl <- table(getMarkers(msn, verbose = FALSE))

## Set class weights as inverse of class frequencies
weights <- 1 / marker_tbl[names(marker_tbl) != "unknown"]

How do we interpret this output?

  • Each row is one iteration of cross-validation. In each iteration, a different random 20% of the markers was held back as a test set, every combination of sigma and cost was tested, and the best-performing combination was recorded.
  • The best parameters are consistent across iterations. Here, sigma = 0.1 and cost = 16 give the highest F1 score in 10 of the 10 iterations. When the same combination wins in most or all iterations, the choice of parameters is stable and does not depend on how the markers happened to be split into training and test sets.
  • The F1 scores are high. They range from 0.82 to 0.88, with a mean of 0.86. The F1 score measures how well the model, trained on one part of the markers, predicts the markers it has not seen, balancing precision and recall. A score of 1 would be perfect, so our classifier correctly predicts most held-out markers. This is also a good sign that our curated markers separate the compartments well.
  • Some variation between iterations is expected. The small spread in F1 scores reflects which markers end up in each test set, and is not a cause for concern.

All parameter combinations with levelPlot

The getF1Scores function only tells us which combination of parameters performed best in each iteration. It does not tell us how the other combinations performed, or whether the best combination is clearly better than its neighbours. For this, we can use the levelPlot function, which shows the F1 score for every combination of sigma and cost tested during optimisation as a heatmap.

## Plot the average F1 score for every combination of sigma and cost
levelPlot(svm_params)

Each cell of the heatmap is one combination of sigma and cost, and its colour shows the F1 score for that combination averaged over the iterations. When reading this plot, we look for three things:

  • Where the highest F1 scores are. This shows us which region of parameter space gives the best classifier, and should agree with the results of getF1Scores.
  • Whether the best region is broad or narrow. A broad region of similarly high F1 scores means the classifier is not very sensitive to the exact parameter values, which is reassuring. A single isolated cell with a high score is less trustworthy, as it may reflect chance.
  • Whether the best values lie at the edge of the grid. If the highest F1 scores are found at the smallest or largest value of sigma or cost tested, a value outside this range might perform even better. In that case, it is worth re-running svmOptimisation with a wider range of values, passed to its sigma and cost arguments.

By default, levelPlot summarises the F1 scores across iterations using the mean. We can change this with the fun argument. For example, using the standard deviation shows how much the performance of each combination varied between iterations.

NoteOther functions for exploring the optimisation

pRoloc has further functions for exploring a GenRegRes object. For example, f1Count(svm_params, t = 0.8) counts how many times each combination of sigma and cost gave an F1 score above a threshold t, and the full F1 matrix for each iteration can be accessed with svm_params@f1Matrices. Extracting the best parameters with getParams

When one combination of sigma and cost performs best in most iterations, the choice is clear. When several combinations perform similarly, the getParams function chooses the best parameters for us. We use it here to confirm the parameters that will be used for classification.

Rather than typing the values of sigma and cost by hand, we pass the whole svm_params object to the assessRes argument, and the best parameters (those returned by getParams) are extracted automatically. 8.2.4 Thresholding protein localisation classification using an SVM

As we saw above, all proteins have been classified to one of the subcellular compartments included in our training data. However, when applying a supervised machine learning algorithm it is standard practice to set a specific confidence threshold at which we accept new assignments. Any protein with a confidence below this threshold will receive the final classification of "unknown". The way in which confidence is defined differs between classification algorithms. In the case of SVMs, we rely on the SVM score to set our thresholds.

Let’s plot a boxplot of the SVM scores of proteins allocated to each subcellular compartment. We first use the unknownMSnSet function to return an MSnSet with the marker proteins removed. Markers are assigned to their own class with a score of 1, so they cannot tell us anything about the confidence of new predictions.

## Remove markers
msn_preds <- unknownMSnSet(object = msn)

## Use the same colours as plot2D for each compartment
org_cols <- getStockcol()[seq_along(getMarkerClasses(msn))]
names(org_cols) <- getMarkerClasses(msn)

## Visualise svm scores per organelle
msn_preds |>
  fData() |>
  as_tibble() |>
  ggplot(aes(x = svm, y = svm.scores, fill = svm)) +
  geom_boxplot(alpha = 0.7, outlier.size = 0.8) +
  scale_fill_manual(values = org_cols) +
  labs(x = "SVM classification", y = "SVM score") +
  theme_bw() +
  theme(axis.text.x = element_text(angle = 45, hjust = 1),
        legend.position = "none")

We can see that each compartment displays a different distribution of SVM scores and, therefore, applying a global score threshold would not be appropriate here. Instead, there are several ways in which users can apply compartment-specific thresholding. One common approach is to manually set a compartment-specific FDR to allow up to 5% false discoveries, for example. This would involve putting the proteins localised to each compartment in descending order by their SVM score before going down the list to find the SVM score at which 5% of proteins are incorrectly classified based on reliable subcellular databases and prior knowledge from the literature. Unfortunately, such an approach can never be completely objective and is limited to organisms with well annotated subcellular proteomes. An alternative method would be to threshold each compartment at a set percentile of its SVM scores. Here, we will demonstrate the latter approach using the orgQuants and getPredictions functions within pRoloc.

The orgQuants function takes an MSnSet containing classification results as its input. We pass the column in our fData where the classification assignments are stored (here "svm"), the score column ("svm.scores") and the marker column ("markers"). Finally, we use the t argument to specify our threshold quantile. The quantile threshold is ultimately up to the user and will depend on (1) how exploratory the analysis aims to be, and (2) the data quality and resolution. In reality, we recommend testing multiple thresholds. Here, we demonstrate the use of a 0.75 quantile threshold, which keeps the 25% of proteins with the highest scores in each compartment.

## Get organelle-specific quantile SVM scores
score_thresholds <- orgQuants(object = msn,
                              fcol = "svm",
                              scol = "svm.scores",
                              mcol = "markers",
                              t = 0.75)

NoteWhy would proteins not meet the classification threshold and remain unknown?

After thresholding our SVM classifications we have 5277 proteins which were not assigned to one of the subcellular compartments and instead remain as "unknown". There are a number of reasons for which proteins may remain unknown after classification. Firstly, the subcellular structure and compartmentalisation of a cell is extremely complex and cannot be completely represented by our labelled training data (markers). For instance, some subcellular structures may have too few well-established marker proteins to be included in classification. This could be due to lack of prior knowledge or absence of a unique protein profile, as seen with P-bodies and stress granules, niches which are defined by many of the same proteins. Secondly, a large proportion of the proteome is known to reside in multiple subcellular niches within a given cell at a given time (Thul et al. 2017). The abundance profiles of these multi-localised proteins can represent a mixture of their localisations and, therefore, no longer match the marker profiles of any given compartment. Further, since correlation profiling experiments utilise bulk proteomics, the observed protein abundance profiles represent an average of the population. Proteins which differ in subcellular localisation across a heterogeneous starting population (e.g., due to differences in cell cycle status) could also display mixed localisation profiles and ultimately remain classified as "unknown".

8.3 Classification using TAGM-MAP

As an alternative to protein localisation classification using a classical SVM approach, users can also make use of newer Bayesian models available within pRoloc. The main advantages of applying a Bayesian framework are that (1) protein localisation predictions come with probabilities, which are on the same scale for every compartment and are, in principle, easier to interpret than SVM scores, and (2) the model includes an outlier component, so proteins that do not fit any of the known compartments can be identified explicitly rather than being forced into one. As we will see, however, these probabilities are only as good as the model that produces them, and they need to be interpreted with care.

Both Bayesian classifiers available within pRoloc are based on a t-augmented Gaussian mixture (TAGM) model, as outlined in Crook et al. (2018). In this course we use the first implementation of this model, TAGM-MAP, which uses maximum a posteriori estimates of the model parameters. The second implementation, TAGM-MCMC, is not covered here (see Crook et al. (2019) for a worked example). Unlike TAGM-MCMC, TAGM-MAP does not sample the entire posterior distribution but instead uses an extended version of the expectation maximisation (EM) algorithm for inference. In terms of user experience, this means that TAGM-MAP is faster and requires less computational power. However, it also means that TAGM-MAP finds a single best set of model parameters and does not account for uncertainty in them. We will return to the consequences of this when we compare the SVM and TAGM-MAP results.

NoteBayesian methods, posteriors and the EM algorithm in brief
  • Bayesian methods combine what we already believe (the prior) with what we observe in the data (the likelihood) to give an updated belief, the posterior. Here, the posterior tells us how probable it is that a protein belongs to each compartment, given its profile and the markers.
  • TAGM (t-augmented Gaussian mixture) describes each compartment as a cloud of points with a centre and a spread (a Gaussian distribution), fitted to the markers. An extra, very broad component (a t-distribution) captures outliers: proteins that do not fit any compartment well.
  • MAP (maximum a posteriori) means finding the single most probable set of model parameters, i.e. the best centre and spread for each compartment.
  • The EM algorithm (expectation maximisation) is how TAGM-MAP finds these parameters. It alternates between two steps: (E) given the current compartment shapes, estimate how likely each protein is to belong to each compartment, and (M) given these estimates, update the compartment shapes. It repeats until the results stop changing, which is why we check convergence.
  • TAGM-MCMC (Markov-chain Monte Carlo), which we do not cover here, does not stop at a single best set of parameters. Instead, it samples many plausible sets, which gives a fuller picture of uncertainty but takes much longer.

8.3.1 Optimising TAGM-MAP model parameters

The first step in using TAGM-MAP is executing the tagmMapTrain function. We run the algorithm for 100 iterations (the default, numIter = 100). We set a seed to ensure reproducibility and pass our marker annotated MSnSet to the function.

## Optimise the tagm-map model
set.seed(2)
map_params <- tagmMapTrain(msn, numIter = 100)

The output of the tagmMapTrain function is an object of class MAPParams which contains the optimised model parameters. Importantly, before applying these parameters we need to check that the model has converged. The TAGM-MAP expectation maximisation (EM) algorithm iterates between an expectation and maximisation step until the log-posterior is stable. To check that the model successfully reached this status, we use the logPosteriors function to extract the log-posteriors at each iteration and pass this to the plot function.

## Plot to visualise convergence
map_params |>
  logPosteriors() |>
  plot(type = "b", col = "blue", cex = 0.3,
       ylab = "log-posterior",
       xlab = "Iteration")

We can see that the value of the log-posterior increased until it stopped changing, thus indicating that the TAGM-MAP model has converged. This means that it is suitable to continue with our optimised parameters. For further details of the algorithm we refer readers to Crook et al. (2019).

8.3.2 Protein localisation prediction with TAGM-MAP

Next, we apply the optimised TAGM-MAP parameters to carry out protein localisation classification via the tagmMapPredict function. We pass our MSnSet object and the object storing our parameters, here called map_params.

## Predict protein localisation using converged parameters
msn <- tagmMapPredict(object = msn, params = map_params)

The tagmMapPredict function adds three new columns to the fData of our MSnSet:

  • tagm.map.allocation: the most probable compartment for each protein. Like the svm column, every protein is assigned to a compartment at this stage, before any thresholding.
  • tagm.map.probability: the probability that the protein belongs to its allocated compartment, given the model. Values close to 1 indicate a confident allocation.
  • tagm.map.outlier: the probability that the protein is an outlier, i.e. that it does not belong to any of the compartments defined by our markers. Values close to 1 indicate a protein that fits poorly with all compartments.

8.3.3 Thresholding protein localisation classification using TAGM-MAP

As was the case when applying an SVM model, we still need to apply thresholding to the initial classification results to ensure confidence in our results. Again, proteins which do not meet our defined threshold will receive the final classification of "unknown". Thresholding of TAGM-MAP outputs can be achieved by combining the probability of a predicted compartment classification being correct with the probability that a protein belongs to an outlier component. In the code chunk below we create a new column in the fData of our MSnSet called overall_prob. This value is calculated as the probability of the compartment classification multiplied by one minus the probability that a protein is an outlier. Hence, a larger overall_prob indicates a higher confidence in our classification.

Because these are probabilities, they are on the same scale for every compartment, so we can use a single threshold for all compartments rather than the organelle-specific thresholds we needed for the SVM. We use the getPredictions function to update our classification predictions based on our score column (scol) overall_prob with a threshold (t) of 0.999.

## Store classification and outlier probabilities
tagm_prob <- fData(msn)[, "tagm.map.probability"]
tagm_out <- 1 - fData(msn)[, "tagm.map.outlier"]

## Create new column containing overall probability
fData(msn)[, "overall_prob"] <- tagm_prob * tagm_out

## Set prediction thresholds on overall probability
msn <- getPredictions(msn,
                      fcol = "tagm.map.allocation",
                      scol = "overall_prob",
                      t = .999)

The SVM scores are spread across the whole range from 0 to 1, so a threshold can separate confident from less confident assignments. The TAGM-MAP probabilities, by contrast, are almost all either very close to 0 or very close to 1. With so few proteins in between, a threshold of 0.999 removes very few proteins, and proteins lying between compartments are classified with a probability of 1.

NoteWhy are the TAGM-MAP probabilities so extreme?

Probabilities are only as good as the model that produces them. There are several reasons why TAGM-MAP tends to be overconfident:

  • TAGM-MAP finds a single best set of parameters. It estimates the centre and spread of each compartment once, and treats these estimates as exact. It ignores any uncertainty in them, which makes the resulting probabilities more extreme than they should be. TAGM-MCMC (not covered here, see Crook et al. (2019)) averages over this uncertainty and generally produces more informative probabilities.
  • Many dimensions sharpen small differences. Our data has 27 quantitative channels (three concatenated replicates). With this many dimensions, a small difference in how well a protein fits two compartments becomes a very large difference in likelihood, pushing the probability towards 0 or 1.
  • Broad compartments absorb proteins between clusters. A compartment with a large spread, such as the ER here, can fit proteins lying between clusters well enough to claim them with high probability.
  • The outlier component may be too small. The expected proportion of outliers is set by a prior (see the u and v arguments in ?tagmMapTrain). If our data contains more proteins that do not fit any compartment than the prior allows for, they are pushed into a compartment instead.

8.5.4 Which results should we use?

There is no single correct answer. Probabilities are attractive because they are on the same scale for every compartment, are easy to interpret, and allow us to identify outliers. However, as we have seen, the probabilities from TAGM-MAP in this dataset are overconfident, and a fixed threshold discriminates poorly between confident and uncertain assignments. There are several ways to address this:

  • use a stricter or organelle-specific threshold on the TAGM-MAP probabilities (see the challenge below)
  • compare the predictions of different classifiers and focus on proteins on which they agree
  • use TAGM-MCMC, which accounts for uncertainty in the model parameters and generally produces more informative probabilities, at a greater computational cost (see Crook et al. 2019)

As with marker curation, the choice depends on the data and the question. Whichever approach is used, predictions should always be checked against the data, using spatial maps and protein profiles, and against prior knowledge.

orgQuants works on any score, so the code runs without error. However, the threshold means something different in each case:

  • SVM scores are not probabilities and are not comparable between compartments, so setting a threshold relative to each compartment’s own score distribution is a sensible way to choose cutoffs.
  • TAGM probabilities are on the same scale for every compartment, so in principle a single threshold such as 0.999 should be enough. A quantile threshold ignores this: it keeps the top 25% of proteins in each compartment, regardless of their actual probability.

In practice, however, the TAGM-MAP probabilities in our data are very close to 0 or 1, so a fixed threshold of 0.999 removes very few proteins. Organelle-specific quantiles bring back some discrimination within each compartment and give results closer to those of the SVM. So, although quantiles do not use the probabilities as probabilities, they can be a useful practical tool when the probabilities are poorly spread. Whichever approach you choose, check the results on a PCA plot and against prior knowledge.

TipKey Points
  • Supervised classifiers predict the localisation of unknown proteins by comparing their correlation profiles with those of the markers. Proteins can only be assigned to compartments represented in the marker list.
  • SVM parameters (sigma and cost) are optimised by repeated cross-validation on the markers with svmOptimisation. Class weights stop the classifier favouring compartments with many markers.
  • getF1Scores shows the best parameters in each iteration and levelPlot shows how every combination performed. Consistent best parameters and high F1 scores indicate a stable, well-performing classifier.
  • svmClassification assigns every protein to a compartment, so predictions must be thresholded. SVM scores differ between compartments, so compartment-specific thresholds (orgQuants, getPredictions) are more appropriate than a single global threshold.
  • TAGM-MAP gives a localisation probability and an outlier probability for each protein. Probabilities are on the same scale for every compartment and are easier to interpret than SVM scores, but they are only as reliable as the model behind them.
  • In our data, TAGM-MAP probabilities are overconfident, so a fixed threshold assigns more proteins than the SVM, particularly in regions between compartments. Visualising predictions on spatial maps, comparing classifiers and choosing thresholds carefully all help to identify confident predictions.
  • Proteins that remain "unknown" after thresholding are not necessarily a problem. They may belong to compartments not in the marker list, reside in more than one location, or vary in localisation across the cell population.
