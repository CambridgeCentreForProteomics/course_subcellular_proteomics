9.2 Spatial maps with different dimensionality reduction methods

The result of classification is a list of proteins and their predicted subcellular localisations. These can be visualised as a “subcellular spatial map” using plot2D, by passing the column containing the predictions to fcol. In the previous lessons we mostly used PCA, the default. However, plot2D supports several other methods, listed in plot2Dmethods (see ?plot2D for details).

plot2Dmethods
 [1] "PCA"    "MDS"    "kpca"   "lda"    "t-SNE"  "UMAP"   "nipals" "hexbin"
 [9] "none"   "scree"

Each method summarises the data in a different way, and no single method shows everything. As discussed in the lesson on assessing resolution, PCA preserves distances but only shows two components at a time, whereas non-linear methods such as t-SNE and UMAP often separate clusters more clearly but distort distances. It is therefore good practice to look at more than one.

9.2.1 Pre-computing coordinates

Non-linear methods such as t-SNE and UMAP can take from a minute to tens of minutes to compute on a dataset of this size. They are also stochastic, so each run gives a slightly different picture unless we set a seed. Rather than recomputing the coordinates every time we make a plot, it is good practice to compute them once, with a seed, and reuse them.

To do this, we pass plot = FALSE to plot2D. Instead of drawing a plot, plot2D then returns a matrix of the two-dimensional coordinates of each protein. Below we pre-compute coordinates for PCA, UMAP, t-SNE and linear discriminant analysis (LDA). LDA is a supervised method: it uses the markers to find the projection that best separates the compartments.

## PCA is deterministic, so we do not need to set a seed
pcas <- msn |>
  plot2D(method = "PCA", plot = FALSE)

## UMAP
set.seed(399)
umap <- msn |>
  plot2D(method = "UMAP", plot = FALSE)

## t-SNE
set.seed(399)
tsne <- msn |>
  plot2D(method = "t-SNE", plot = FALSE)

## Linear discriminant analysis (uses the markers column)
set.seed(399)
lda <- msn |>
  plot2D(method = "lda", plot = FALSE)

Each object is a matrix with one row per protein and two columns.

9.2.2 Plotting pre-computed coordinates

We can now pass these coordinates back to plot2D with method = "none", which tells plot2D not to compute anything. Because a matrix of coordinates does not contain the feature data, we also pass our MSnSet to methargs so that plot2D knows where to find the fcol annotation.

par(mfrow = c(2, 2))
plot2D(pcas, method = "none", methargs = list(msn),
       fcol = "svm.pred", main = "PCA")
plot2D(umap, method = "none", methargs = list(msn),
       fcol = "svm.pred", main = "UMAP")
plot2D(tsne, method = "none", methargs = list(msn),
       fcol = "svm.pred", main = "t-SNE")
plot2D(lda, method = "none", methargs = list(msn),
       fcol = "svm.pred", main = "LDA")
addLegend(msn, fcol = "svm.pred", where = "topright", ncol = 2, cex = .7)

The same compartments are found in all four maps, but each method shows them differently. Compartments that overlap in the PCA plot may be clearly separated in the t-SNE or UMAP plots, and vice versa. Remember that distances between clusters in t-SNE and UMAP plots cannot be interpreted directly.

9.3 Compartment fingerprints with plotConsProfiles

Spatial maps show where proteins lie relative to each other, but they hide the profiles themselves. A compact way to summarise the profiles of a whole class is to calculate its consensus profile, the average profile of the proteins in that class, and display all of these together as a heatmap. Each row is a compartment, each column a fraction, and the colour shows the consensus profile. This gives a “fingerprint” of each compartment across the fractionation gradient.

This takes three steps in pRoloc:

  1. mrkConsProfiles calculates the consensus profile of each compartment and returns a matrix with one row per compartment and one column per fraction.
  2. mrkHClust clusters the compartments by their consensus profiles. We use the resulting dendrogram to order the rows of the heatmap, so that compartments with similar profiles are next to each other.
  3. plotConsProfiles plots the matrix as a heatmap, in the given order.
## 1. Consensus profile of each marker class
fmat <- mrkConsProfiles(msn, fcol = "markers")
dim(fmat)
[1] 13 27
## 2. Order the classes by hierarchical clustering of their profiles
hc <- mrkHClust(msn, fcol = "markers", plot = FALSE)
mm <- getMarkerClasses(msn, fcol = "markers")
ord <- levels(factor(mm))[order.dendrogram(hc)]
ord
 [1] "Chromatin"     "Mitochondrion" "Golgi"         "Lysosome"     
 [5] "ER"            "PM"            "Endosome"      "Peroxisome"   
 [9] "Cytosol"       "Proteasome"    "Nucleus"       "Ribosome 40S" 
[13] "Ribosome 60S" 
## 3. Plot the consensus profiles of the markers
plotConsProfiles(fmat, order = ord)

Each compartment has a distinct fingerprint, with its abundance peaking in different fractions, and the pattern is repeated in each of the three replicates. Compartments next to each other in this plot have similar fingerprints and are harder to separate, which is consistent with what we saw with QSep in the data annotation lesson.

We can make the same plot for the SVM predictions by passing fcol = "svm.pred" to mrkConsProfiles. Proteins left as "unknown" are not included. We reuse the order from the markers so that the two plots can be compared row by row. If the classification is sensible, the newly classified proteins should keep the fingerprint of their compartment.

## Consensus profiles of the SVM predictions, in the same order as the markers
fmat_svm <- mrkConsProfiles(msn, fcol = "svm.pred")
plotConsProfiles(fmat_svm, order = ord)

The fingerprints of the predictions are usually a little less sharp than those of the markers, because the classified proteins include proteins that lie further from the centre of each compartment. A compartment whose fingerprint changes markedly would be worth investigating further.

9.4 Peptide support and missing values

All of the maps we have made so far treat each protein equally. However, some proteins are quantified from many precursors, whilst others rely on only one or two. Similarly, some profiles are complete, whereas others were partly filled in by imputation. Proteins with little peptide support or many missing values tend to have noisier profiles, which can place them between clusters on a map or prevent them from being classified confidently. Overlaying this information on our maps helps us to interpret them.

9.4.1 Peptide support across the combined data

At the end of part 1 we added the number of precursors supporting each protein in each replicate (n_rep1, n_rep2, n_rep3), together with their minimum (n_min). We use the minimum because a protein is only as well supported as its weakest replicate: a protein with 12, 10 and 1 precursors has a reasonable mean, but its profile in the third replicate rests on a single precursor.

## Summary of the minimum number of precursors per protein
msn |>
  fData() |>
  pull(n_min) |>
  summary()
   Min. 1st Qu.  Median    Mean 3rd Qu.    Max. 
   1.00    4.00    9.50   14.74   19.00  474.00

We can show peptide support on a spatial map by scaling the size of each point. The plot2D function accepts a vector of point sizes through its cex argument. We use a log scale, so that the few proteins with very many precursors do not dominate the plot.

## Point size based on the (log) minimum number of precursors
ptsze <- 0.3 + log2(fData(msn)$n_min) / 3

plot2D(pcas, method = "none", methargs = list(msn),
       fcol = "svm.pred", cex = ptsze,
       main = "PCA: SVM predictions, sized by peptide support")
addLegend(msn, fcol = "svm.pred", where = "topright", cex = .6)

Large points are well supported proteins, and small points are proteins supported by few precursors in at least one replicate. Look at where the small points lie: are they spread evenly across the map, or concentrated in particular regions, such as between clusters?

9.4.2 Missing values across the combined data

We can do the same for missing values. The missing_max column gives, for each protein, the largest proportion of values that were missing before imputation in any one replicate. Again, a profile is only as reliable as its weakest replicate.

## Summary of the maximum proportion of missing values per protein
msn |>
  fData() |>
  pull(missing_max) |>
  summary()
   Min. 1st Qu.  Median    Mean 3rd Qu.    Max. 
 0.0000  0.3194  0.4444  0.4598  0.5926  0.7778

This time we make points smaller as the proportion of missing values increases, so that large points are still the most reliable proteins.

## Point size decreases with the proportion of missing values
ptsze_na <- 1.5 * (1 - fData(msn)$missing_max)

plot2D(pcas, method = "none", methargs = list(msn),
       fcol = "svm.pred", cex = ptsze_na,
       main = "PCA: SVM predictions, sized by completeness")
addLegend(msn, fcol = "svm.pred", where = "topright", cex = .6)

9.4.3 Comparing compartments

We can now ask directly whether peptide support and missing values differ between compartments, and in particular whether the proteins left as "unknown" tend to be less reliable. We put both columns in long format and plot them side by side.

## Colours for each compartment, with unknown in grey
classes <- getMarkerClasses(msn)
pred_cols <- c(setNames(getStockcol()[seq_along(classes)], classes),
               unknown = getUnknowncol())

## Peptide support and missing values per predicted compartment
msn |>
  fData() |>
  as_tibble() |>
  pivot_longer(c(n_min, missing_max), names_to = "measure", values_to = "value") |>
  ggplot(aes(x = svm.pred, y = value, fill = svm.pred)) +
  geom_boxplot(alpha = 0.7, outlier.size = 0.8) +
  facet_wrap(~ measure, scales = "free_y",
             labeller = as_labeller(c(n_min = "Minimum number of precursors",
                                      missing_max = "Maximum proportion missing"))) +
  scale_fill_manual(values = pred_cols) +
  labs(x = "SVM prediction", y = NULL) +
  theme_bw() +
  theme(axis.text.x = element_text(angle = 45, hjust = 1),
        legend.position = "none")

The two measures are related: proteins with few precursors often have more missing values, because there are fewer precursors to fill in the gaps. Look at whether any compartment, or the "unknown" proteins, stand out on either measure. Do you think this is biological or technical?

9.4.4 Peptide support and missing values in each replicate

The minimum and maximum hide which replicate is responsible for a poorly supported or incomplete profile. To see this, we return to the data of each replicate in our QFeatures object, before the replicates were joined, as we did in the lesson on assessing resolution. Let’s store the names of these sets (from our QFeatures object) so that we can coerce them into individual MSnSets for plotting.

## Save names of normalised protein-level sets for each replicate, before joining
rep_sets <- c(rep1 = "proteins_norm_R1",
              rep2 = "proteins_norm_R2",
              rep3 = "proteins_norm_R3")

## Create normalised protein-level MSnSets for individual replicates
for (i in 1:length(rep_sets)) {
  
  se <- qf[[rep_sets[i]]] # Extract protein-level set
  msnset <- as(se, "MSnSet") # Convert to MSnSet
  assign(names(rep_sets[i]), msnset) # Assign name to MSnSet
}

The normalised protein-level replicate sets already contain the .n column that was generated when summarising precursor to protein level data using the aggregateFeatures function.

However, since we imputed before normalising, the normalised data does not contain information about missing values. Instead, we had added this to the pre-normalised protein-level replicate sets (named "proteins_R1", "proteins_R2" and "proteins_R3") by creating the prop_missing column. Therefore, we copy this column to our normalised protein MSnSets for each replicate, so that we can use it for plotting.

## Store names of individual replicate MSnSets
msnset_reps <- c(rep1, rep2, rep3)

agg_sets <- c(rep1 = "proteins_R1",
              rep2 = "proteins_R2",
              rep3 = "proteins_R3")

## Add prop_missing to the individual replicate MSnSets with normalised protein data
for (i in 1:length(rep_sets)) {
  
  msnset <- msnset_reps[[i]]
  protein_set <- qf[[agg_sets[i]]]
  
  fData(msnset)$prop_missing <- rowData(protein_set)$prop_missing
  
  assign(names(rep_sets)[i], msnset)
  
}

Our classification was carried out on the combined data. To colour the replicate maps, we copy the SVM predictions across by matching protein accessions. Proteins that were not part of the combined data (for example, because they were missing from another replicate) are labelled "unknown".

## Copy the SVM predictions from the combined data to each replicate
for (i in names(msn_reps)) {
  
  ids <- featureNames(msn_reps[[i]]) # Extract featureNames from each MSnSet
  pred <- fData(msn)[ids, "svm.pred"] # Extract classifications from each MSnSet
  pred[is.na(pred)] <- "unknown" # Set remaining proteins as unknown
  
  fData(msn_reps[[i]])$svm.pred <- pred # Add classifications from concatenated data to individual reps
}

We can now plot each replicate, with points sized by that replicate’s peptide support. To size the points by completeness instead, replace the cex argument with 1.5 * (1 - fData(msn_reps[[r]])$prop_missing).

par(mfrow = c(1, 3))
for (i in names(msn_reps)) {
  
  plot2D(msn_reps[[i]], fcol = "svm.pred",
         cex = 0.3 + log2(fData(msn_reps[[i]])$n) / 3,
         main = paste("PCA:", i))
}

Each replicate has its own PCA, so the plots may be rotated or mirrored relative to each other. What matters is that the same structure appears in each. Plotting replicates separately in this way is also a useful check that the replicates agree, and that no single replicate has noticeably lower peptide support, more missing values or poorer resolution than the others.

9.5 Overlaying protein complexes

Users may wish to add further information to their maps, for example protein complexes, pathways of interest, or compartments that were not used as training data because they lacked resolution or had too few marker proteins. Protein complexes are a particularly nice example, because their members are expected to be found together, and related complexes can reveal how finely our data resolves the cell.

9.5.1 Finding complex members by gene name

To find the members of a complex, it is convenient to search the feature data by gene name. Our data contains a column of gene names from DIA-NN (here Genes; check fvarLabels(msn) for the name in your data). Where several genes map to the same protein group, they are separated by a semicolon, so we write a small helper function that splits these and searches each gene name against a pattern.

## Return the proteins whose gene name(s) match a regular expression
find_genes <- function(object, pattern, gcol = "Genes") {
  genes <- strsplit(as.character(fData(object)[[gcol]]), ";")
  hit <- vapply(genes, function(g) any(grepl(pattern, g)), logical(1))
  featureNames(object)[hit]
}

The pattern is a regular expression. For example, "^ATP6V1" matches all gene names starting with ATP6V1, and "^(TCP1|CCT[2-8][AB]?)$" matches TCP1 and CCT2 to CCT8 (including CCT6A and CCT6B) exactly. You can also use the pRolocVis app (pRolocVis(msn, fcol = "svm.pred")) to search the feature data interactively.

9.5.2 A well-behaved complex: the TRiC chaperonin

The TRiC (or CCT) chaperonin is a large cytosolic complex of eight different subunits that helps newly made proteins to fold. We expect its subunits to be found together, making it a good first example.

## Return featureNames for members of the TRiC chaperonin

The map shows where the complex lies. To see why, we can compare the profiles of its members with those of the cytosolic markers using plotDist. The markers argument tells plotDist which proteins to highlight, here the TRiC subunits in black, while the cytosolic markers are plotted in grey.

## Cytosol markers

         markers = tric, type = "l",

         las = 2)
title("TRiC subunits (black) and cytosol markers (grey)")

9.5.4 Adding complexes as a new fData column

Alternatively, we can store our annotations in a new column of the feature data, just as we did for markers. This keeps the annotation with the data and allows us to use all the usual plotting functions. The easiest way is to create a named vector, with the annotation as values and the protein accessions as names, and add it with addMarkers. All proteins not in the vector are labelled "unknown".

As an example, we look at the vacuolar ATPase (V-ATPase), the proton pump that acidifies lysosomes and endosomes. It has two parts: V0, which sits in the membrane, and V1, which assembles onto V0 from the cytosol and can come off again. Do the two parts sit in the same place on our map?

## V-ATPase V1 and V0 subunits
v1 <- find_genes(msn, "^ATP6V1")
v0 <- find_genes(msn, "^ATP6V0")

## Named vector of annotations
vatpase <- c(rep("V-ATPase V1", length(v1)),
             rep("V-ATPase V0", length(v0)))
names(vatpase) <- c(v1, v0)

## Add as a new fData column called "vatpase"
msn <- addMarkers(msn, markers = vatpase, mcol = "vatpase")
Markers in data: 13 out of 8736
organelleMarkers
    unknown V-ATPase V0 V-ATPase V1 
       8723           5           8

We can now pass this column to fcol to plot a map in which only the V-ATPase subunits are coloured.

par(mfrow = c(1, 2))
plot2D(pcas, method = "none", methargs = list(msn),
       fcol = "vatpase", cex = 1.5, main = "PCA: V-ATPase")
addLegend(msn, fcol = "vatpase", where = "topleft", cex = .8)
plot2D(tsne, method = "none", methargs = list(msn),
       fcol = "vatpase", cex = 1.5, main = "t-SNE: V-ATPase")

The same approach can be used for any annotation, for example proteins from a pathway of interest, proteins identified in another experiment, or a compartment that was not included in the training data.

If the members of the complex are mostly "unknown", the most common prediction will be "unknown" and there will be no markers to compare with. In that case, choose the compartment by looking at the map instead.

TipKey Points
  • Spatial maps of classification results are made with plot2D by passing the prediction column to fcol. Different dimensionality reduction methods show the data in different ways, so it is good practice to look at more than one.
  • Pre-computing coordinates with plot = FALSE, using a seed for stochastic methods, and reusing them with method = "none" makes figures faster and reproducible.
  • mrkConsProfiles calculates the consensus profile, or fingerprint, of each compartment, and plotConsProfiles displays them as a heatmap, ordered by similarity using mrkHClust.
  • Peptide support and missing values can be shown on spatial maps by scaling point size. Proteins supported by few precursors, or with many values imputed, tend to have noisier profiles, so these measures help to interpret their position on the map and their classification. Plotting replicates separately shows which replicate is responsible.
  • Members of protein complexes can be found by gene name, highlighted on any map with highlightOnPlot, and stored as new fData columns with addMarkers. Comparing their profiles with those of their compartment using plotDist shows why they lie where they do.
